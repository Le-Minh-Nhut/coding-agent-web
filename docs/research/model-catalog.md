# Model catalog enumeration

## Mechanism

OMP exposes a non-interactive, machine-readable catalog command: `omp models --json`. On this installed OMP `v18.12.2`, it returned valid JSON without launching a coding-agent session or making an inference/model-generation request. The command code constructs `AuthStorage`, `ModelRegistry`, refreshes with `online-if-uncached`, and renders JSON (`/tmp/omp-v18.12.2/packages/coding-agent/src/commands/models.ts:13-45,56-70`; `/tmp/omp-v18.12.2/packages/coding-agent/src/cli/models-cli.ts:385-426`). The registry's default discovery strategy may use fresh caches, bundled catalogs and local config; when it fetches eligible provider catalogs it may use configured provider discovery. It explicitly does not run `!command` credential/header helpers unless an explicit refresh requests them (`/tmp/omp-v18.12.2/packages/coding-agent/src/config/model-registry.ts:276-285,550-563,2034-2060`). Thus enumeration is safe from agent-turn/provider-inference credits, but **not guaranteed offline**: uncached/stale provider catalog discovery can require provider credentials and network. The adapter calls ordinary `models --json`, never `models refresh`; if strict no-network enumeration is required, a complete current catalog is not guaranteed by this API. The command may inspect local provider endpoints and configured extensions, which is why it uses OMP's own CLI rather than reading `models.db` directly.
Adapter runs OMP with `execFile` argv and `shell: false`, 15s timeout and 8 MiB stdout bound. On any executable/exit/parse/output problem it returns `[]`, not a fabricated list.

## Listing format and ordering

`omp models --json` returns `{ "models": [...] }`; each row includes `provider`, `kind`, `id`, `selector`, display name, reasoning flag and separate supported `thinking` levels, among other metadata (`/tmp/omp-v18.12.2/packages/coding-agent/src/cli/models-cli.ts:74-92,116-132,229-237`). The exact selector is OMP's `provider/id`, which can contain additional slashes within `id`: captured rows include `cx/cx/gpt-6-luna` (provider `cx`, id `cx/gpt-6-luna`) and `cx/wdb/deepseek-ai/DeepSeek-V4.1-Flash` (provider `cx`, id `wdb/deepseek-ai/DeepSeek-V4.1-Flash`). Preserve `selector`; don't reconstruct it from assumptions about exactly one slash. Adapter returns unique selectors sorted by provider, then full model id, using locale comparison. It drops malformed rows and requires OMP's `selector` to match its `provider` + `id` exactly.

Thinking-level suffixes are a separate selector dimension, not expanded rows: listing row has base model selector and `thinking: [...]` supported-effort list, while `formatModelSelectorValue` adds `:<level>` only when a concrete thinking level is selected (`/tmp/omp-v18.12.2/packages/coding-agent/src/cli/models-cli.ts:116-132`; `/tmp/omp-v18.12.2/packages/tui/src/overlays/model-selector.ts:81-83`). Keep catalog identifiers un-suffixed. If runtime needs a selected effort later, store/compose it separately or as an explicit selector suffix. Do not also send coarse `effort` when suffix must win: caller `effort` outranks explicit `:level` (`docs/operations/subagent-effort-policy.md:5-25`).

The TUI's model picker receives the same `ModelRegistry` and `session.scopedModels`; the `ModelPickerComponent` reads the scoped catalog and refreshes the registry when scope permits (`/tmp/omp-v18.12.2/packages/coding-agent/src/modes/controllers/selector-controller.ts:806-850`; `/tmp/omp-v18.12.2/packages/tui/src/overlays/model-picker.ts:119-160,206-230`). Registry available models are filtered by enabled providers and configured auth (`/tmp/omp-v18.12.2/packages/coding-agent/src/config/model-registry.ts:2993-3005,3014-3069`). `omp models --json` is thus the supported CLI list surface, not an approximation from `models.db` or settings.

## Other surfaces checked

- `omp --help` documents launch model flags (`--model`, `--models`, `--thinking`), not a catalog dump. `omp models --help` documents `ls`, `find`, `refresh`, `--json`, `--kind`, extension/config options. `omp models --json` is the machine listing; `omp models refresh` is deliberately not used because it explicitly forces catalog fetch and credential refresh (`packages/coding-agent/src/commands/models.ts:26-53,56-70`; `cli/models-cli.ts:385-408`).
- RPC has `get_available_models`, but it runs on a launched RPC session, not as a zero-session catalogue API. That command waits for the RPC session's registry background refresh before returning `session.getAvailableModels()` (`/tmp/omp-v18.12.2/packages/coding-agent/src/modes/rpc/rpc-types.ts:80-88`; `/tmp/omp-v18.12.2/packages/coding-agent/src/modes/rpc/rpc-mode.ts:2287-2291`; SDK client `/tmp/omp-v18.12.2/packages/coding-agent/src/modes/rpc/rpc-client.ts:943-949`). It is unnecessary for listing and has the wrong lifecycle boundary for this app.
- OMP stores model-discovery rows in `~/.omp/agent/models.db`, a SQLite cache, with freshness and provider-specific semantics; it is not the complete authoritative catalog (bundled static models, current config, credentials, enabled-provider policy, extensions and discovery state all feed registry composition; see `model-registry.ts:517-563,1356-1370,2034-2060,2993-3069`). Reading raw DB rows would bypass that composition. The registry has a 24-hour cache TTL (`model-registry.ts:1357,2036`; `refreshRuntimeProviders` docs at `883-890`).

## Adapter contract and handoff

`ModelCatalogService.listModels(): Promise<string[]>` is implemented by `DefaultModelCatalogService` in `packages/omp-adapter/src/model-catalog.ts` and exported from `packages/omp-adapter/src/index.ts`. Array contains exact, deduplicated OMP `selector` strings, provider/id sorted. Empty means unknown or no available entries; the current signature deliberately does not distinguish an empty catalog from missing/unreadable/unsupported OMP, so callers must not replace it with a hardcoded fallback.

Server/web handoff: instantiate `DefaultModelCatalogService` in adapter wiring and call `listModels()` for a model-options endpoint; render returned selectors in a searchable dropdown while preserving stored preference even when it is absent from current results. If the list is empty, show the existing free-text model field unchanged and keep save/restart working; empty is not proof that a saved custom/current selector is invalid. Do not wire from RPC or read `models.db` directly. No app/server/web code was changed in this workstream.
