# OMP remote slash-command feasibility

## Scope and source identity

Observed installed CLI: `omp --version` → `omp/18.12.2`; `omp --help` exposes normal launch flags/subcommands, including `--mode rpc`, `--thinking`, `--advisor`, `--model`, `collab`, and `join`. Retrieved upstream source from `https://github.com/can1357/oh-my-pi`, tag `v18.12.2`, into `/tmp/omp-v18.12.2`; checkout resolves to commit `1d5aff90b057ce7dbfe32ea557a527c1b3144b72`. Upstream package also declares version 18.12.2 (`packages/coding-agent/package.json:1-4,21-28`). The repository's vendored guest provenance identifies the same upstream and version (`packages/guest/UPSTREAM.md:3-7`), but that guest is not the OMP host or command implementation.

This is source investigation only. No agents were launched, no provider credits spent, and no build/test/smoke check run.

## Dispatcher and `/` prompt verdict

Interactive TUI uses `executeBuiltinSlashCommand` over a unified registry assembled from mode, collaboration, session, lifecycle, marketplace, skills, and control groups (`packages/coding-agent/src/slash-commands/builtin-registry.ts:42-58,134-159`). Its input caller dispatches built-ins before regular prompt delivery; when running as a Collab guest, it then rejects remaining slash-prefixed text as host-only rather than forwarding it (`packages/coding-agent/src/modes/controllers/input-controller.ts:1068-1098,1101-1125`). The guest-local allowlist is explicitly read-mostly (`packages/coding-agent/src/collab/guest.ts:49-64`).

A Collab `prompt` frame has only text and optional images; it is not a remote slash-command request (`packages/wire/src/index.ts:328-344`). Host frame handling switches on frame type and calls `#handlePrompt(frame.text, ...)` (`packages/coding-agent/src/collab/host.ts:717-742`). That handler verifies write permission, wraps the provided text as a `custom_message` with `customType: "collab-prompt"`, and submits via `session.promptCustomMessage(...)` (`packages/coding-agent/src/collab/host.ts:978-1011`). `promptCustomMessage` dispatches a custom message, builds it with `role: "custom"`, then hands it to `#promptWithMessage` (`packages/coding-agent/src/session/agent-session.ts:7854-7855,7878-7883,7931-7938,7976-7983`); this path does **not** call the interactive slash dispatcher. So `/model` (or any other `/...`) sent as Collab prompt text becomes agent-context content, not execution of that built-in. The normal TUI's deliberate host-only guest guard makes this explicit. OMP's normal `session.prompt(...)` has separate slash expansion behavior, but Collab uses `promptCustomMessage`, not that parser path.

The app's own browser composer does not reject leading `/`: it sends the typed string as `t: "prompt"` (`apps/web/src/components/ConversationView.tsx:429-449`). Consequently, typing `/model` there reaches the host as Collab custom-message content; it does not invoke `/model`. The upstream TUI guest rejects host-only slash commands locally (`input-controller.ts:1101-1108`), but the app's composer itself has no such guard.

## Programmatic surfaces

- **CLI launch flags and subcommands:** launch-time configuration, not a control socket for an existing interactive process. `omp --mode rpc` is the documented newline-delimited JSON-over-stdio interface (`docs/rpc.md:1-23`); print/headless prompt is `omp -p ...`, and launch flags such as `--model`, `--thinking`, `--advisor`, and `--goal` configure new launches (`docs/cli-reference.md:33-53,100-148`). `omp join <link>` starts an interactive TUI and runs `/join`; it is not a command API for an already running host (`packages/coding-agent/src/commands/join.ts:1-39`).
- **RPC/IPC:** RPC supports live session prompt/steer/follow-up/queue removal/promotion/abort, `new_session`, `goal`, model selection, thinking levels, queue modes, and compaction (`packages/coding-agent/src/modes/rpc/rpc-types.ts:35-97`; fuller schema in `docs/rpc.md:126-188`). The documented RPC transport is the child process's stdio, not an endpoint attached to an existing TUI (`docs/rpc.md:3-23`). The SDK's `RpcClient` exposes methods for prompt, abort, goal, model, thinking and compact (`packages/coding-agent/src/modes/rpc/rpc-client.ts:692-742,828-840,923-1021`). RPC prompt dispatch itself checks skill handlers and the ACP/text builtin dispatcher before `session.prompt(...)` (`packages/coding-agent/src/modes/rpc/rpc-mode.ts:1788-1849`); thus slash built-ins with a text-mode `handle` can execute *when the caller deliberately uses the RPC prompt API*. This does not make Collab prompt frames command calls.
- **Upstream Collab local IPC registry:** `omp collab list/link` discovery IPC is intentionally limited to authenticated `snapshot` and generation-bound `link`; unknown operations fail. It exposes no session command/prompt endpoint (`packages/coding-agent/src/collab/registry.ts:1-24,290-354`; `docs/collab.md:73-91`).
- **Collab host prompt/control handler:** supports native `prompt`, `abort`, `agent-cmd` (subagent chat/kill/revive), transcript fetch, and UI response; these are explicit frame types, not arbitrary command execution (`packages/wire/src/index.ts:328-344`; `packages/coding-agent/src/collab/host.ts:717-742,978-1011,1150-1199`). There is no model-switch, compact, clear, goal, advisor, or thinking control frame. Compaction/model/thinking change entries and state may be *replicated outward* but are not guest-to-host control frames (`packages/wire/src/index.ts:134-198,328-344`).

## What the app exposes today

- **Prompt:** `ConversationView` sends `{t:"prompt", text}` over the Collab socket; its local `user-${++localIdRef.current}` value labels only the optimistic transcript row and is not sent (`apps/web/src/components/ConversationView.tsx:302-325`). The upstream prompt frame has no idempotency key (`packages/wire/src/index.ts:328-344`), and the host invokes `promptCustomMessage` using text/images only (`packages/coding-agent/src/collab/host.ts:725-728,978-1003`). A manual resend after an ambiguous disconnect can enqueue duplicate work; `MetadataStore.recordCommandOnce()` exists but has no production caller (`apps/server/src/store.ts:27,162-172`).
 - **Interrupt:** Stop button sends Collab `abort` (`ConversationView.tsx:451-457`), handled by OMP Collab host's interrupt case (`host.ts:729-732`).
 - **Model:** app has a model text field. PATCH `/api/conversations/:id/model` updates `modelPreference`; it does not contact live OMP (`apps/server/src/app.ts:346-351`). Save-and-restart saves first, then restarts the managed session (`app.ts:353-375`; `ConversationView.tsx:459-488`). This is preference-at-launch, not live selector.
 - **Approvals:** app handles inbound Collab `ui-request`/`ui-request-end`, shows responses, and sends `ui-response` (`ConversationView.tsx:299-321,491-516`). Its FIFO queue is pending UI requests, not queued user prompts (`ConversationView.tsx:95-100,299-321`).
 - **Subagents:** app receives roster/transcript-fetch responses and sends `fetch-transcript` (`ConversationView.tsx:295-297,324-338,519-528`). It does not send `agent-cmd` chat/kill/revive frames. Upstream protocol defines those actions (`packages/wire/src/index.ts:343-344`) but current web app doesn't expose them.
 - **No slash-command endpoint:** app routes include link minting, model preference, and lifecycle `stop`/`restart`; none accepts a slash string (`apps/server/src/app.ts:294-318,346-379`). `commandSchema` exists in contracts (`packages/contracts/src/index.ts:339-344`), but inspected app routes do not consume it. User composer text including `/...` only takes Collab path above.
 - App-owned tmux actions are lifecycle start/stop and a copyable `tmux attach` instruction, not key injection. Runtime launch is recorded by tmux session ID, server identity and pane PID (`packages/runtime/src/supervisor.ts:462-470`; `packages/omp-adapter/src/tmux.ts:179-217`). The attach route verifies server identity and emits an attach command (`apps/server/src/app.ts:319-344`).

## tmux `send-keys` bridge verdict

**Do not build it as a slash-command bridge.** Repo does have an adapter `sendKeys(sessionId, keys)`, but it validates only a `$N` session-shaped ID and calls `tmux send-keys -t <sessionId> <keys>`; it does not verify recorded pane PID/server identity at send time or encode input as literal editor text (`packages/omp-adapter/src/tmux.ts:242-256`). Runtime separately records identity/PID for launch and has identity-checked stop logic, but no equivalent guarded send operation (`packages/runtime/src/supervisor.ts:462-470,663-701`).

| Safety claim | Can source prove it? | Reason |
| --- | --- | --- |
| Targets correct process (`session_id`/pane PID) | **No** | Existing method targets a tmux session ID and default pane, not the recorded pane PID. Session listing exposes `session_id`, `pane_pid`, server identity, but there is no atomic identity-check-plus-send path (`tmux.ts:127-166,242-248`). A prior PID check would still race a target change. |
| Does not interfere with active turn | **No** | `send-keys` has no turn-state guard. Collab registry `busy` can be unknown and may be false during scheduling pauses; neither makes terminal keystrokes a safe steer (`docs/collab.md:83-85`). Native Collab already provides deliberate steering and abort controls. |
| Does not corrupt terminal editor state | **No** | tmux routes key events into the live TUI; source has no bridge protocol for editor focus, draft, modal, prompt/compaction state or terminal escape sequences. |
| Does not inject unintended keystrokes | **No** | Adapter forwards `keys` as a tmux key argument without a literal-text/keystroke allowlist or mode-aware escaping (`tmux.ts:242-248`). `send-keys` is explicitly a keyboard injection surface, not a command API. |
| Does not bypass native session ownership | **No, not as a safety guarantee** | It does not launch a second OMP PID, but it bypasses Collab's explicit writable-peer frame/handler boundary by writing into the host TUI; if the owner is also attached, both can drive the same input/editor. Current source has no authorization, turn arbitration, or guarded ownership contract for this path. |

A future need for remote commands should use a deliberate API/frame routed to the existing OMP session, or a separately supervised RPC process where changed session/terminal continuity is an accepted tradeoff. Do not infer safe remote keystrokes from having a recorded tmux session ID.

## Minimum honest remote command set

Today, advertise only **send prompt**, **interrupt/stop**, **answer host UI requests**, and **read transcript/state** as remote Collab controls. Advertise model change only as **save preference for next launch / restart**, not live model switching. Do not advertise `/...` as executable commands or implement tmux keystroke injection. If additional native session controls become a requirement, define explicit, validated control actions rather than forwarding slash text.
