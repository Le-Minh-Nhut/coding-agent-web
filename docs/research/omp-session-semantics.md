# OMP Session Semantics, Persistence, and Concurrency Research

Ground truth for Oh My Pi (OMP) v18.12.2 session persistence, on-disk structure, lifecycle semantics, and concurrent-writer safety.

---

## 1. Session On-Disk Layout & Keying

### Directory Encoding
Sessions live under `~/.omp/agent/sessions/<encoded-cwd>/` (or `$PI_CODING_AGENT_DIR/sessions/<encoded-cwd>`).
The directory name `<encoded-cwd>` is deterministically derived from the canonical project working directory (`resolveEquivalentPath(path.resolve(cwd))`):
- **Within Temp Root** (`os.tmpdir()`): `-tmp-<tempRelative>` (all path separators `/`, `\`, `:` replaced with `-`).
- **Within Home Root** (`os.homedir()`): `-<homeRelative>` (all path separators replaced with `-`).
- **Outside Home/Temp**: `--<encoded-absolute>--` (leading slash stripped, path separators replaced with `-`).

*Source:* `packages/coding-agent/src/session/session-paths.ts:77-128` (`getDefaultSessionDirName`).

### File and Artifact Naming
A session journal is a JSONL file:
```text
<fileSafeTimestamp>_<sessionId>.jsonl
```
- `<fileSafeTimestamp>`: ISO-8601 UTC timestamp (`nowIso()`) with `:` and `.` converted to `-` via `iso.replace(/[:.]/g, "-")`.
- `<sessionId>`: UUIDv7 generated by `Bun.randomUUIDv7()`.
- **Artifacts directory**: stripped `.jsonl` suffix, yielding `<fileSafeTimestamp>_<sessionId>/`. Subagent sessions and MCP truncation artifacts live inside this folder.

*Source:* `packages/coding-agent/src/session/session-manager.ts:158-166,2046-2050`.

### Real Example Path (Structure Only)
From this host:
- Project cwd: `/home/heheboiz/data/coding-agent-web`
- Session directory: `~/.omp/agent/sessions/-data-coding-agent-web/`
- Journal file: `~/.omp/agent/sessions/-data-coding-agent-web/2026-10-24T16-45-17-909Z_01a16ecd-68d5-76e3-ad97-6bd95f2efad3.jsonl`
- Artifacts directory: `~/.omp/agent/sessions/-data-coding-agent-web/2026-10-24T16-45-17-909Z_01a16ecd-68d5-76e3-ad97-6bd95f2efad3/`

### `--session-dir` Behavior
Passing `--session-dir=<path>` sets `this.#sessionDir = path.resolve(sessionDir)` and creates it (`storage.ensureDirSync`).
- Directs session persistence, resume discovery, and recent session listings to that explicit directory instead of the cwd-derived folder.
- Disables automatic worktree discovery and global fallback resolution (`allowGlobalFallback: false`).

## 3. CLI Flag Semantics & Verbatim Strings

### Verbatim Flag Lines from `omp --help`
```text
  -c, --continue                        Continue previous session
  -r, --resume=<value>                  Resume a session (by ID prefix, path, or picker if omitted)
      --restore=<value>                 Resume a session as --resume does, then go on with what its last process left unfinished (the interrupted turn and the subagents it was running)
      --session-dir=<value>             Directory for session storage and lookup
      --no-session                      Don't save session (ephemeral)
```
*(Note on `--fork`: Accepted by `STRING_SETTERS["--fork"]` in `packages/coding-agent/src/cli/flag-tables.ts:140` and documented in `cli-reference.md`, but not rendered in the top-level `omp --help` summary list).*

### Detailed Semantics
- **`--resume=<value>` (`-r`)**: Resumes a session by full file path, UUIDv7 ID prefix, or filename prefix. When invoked bare (`omp -r`), opens an interactive picker of recent sessions. Requires persistent storage.
- **`--continue` (`-c`)**: Resumes the single most recent session for current `cwd`. Checks terminal breadcrumbs in `~/.omp/agent/terminal-sessions/<ttyid>` first (respecting empty `/new` boundaries), falling back to newest `.jsonl` by mtime.
- **`--restore=<value>`**: Resumes an interrupted session like `--resume`, then immediately revives the interrupted turn and restarts child subagents running when the prior process crashed/terminated. Interactive only; mutually exclusive with prompts, `--continue`, `--fork`, `--goal`.
- **`--session-dir=<value>`**: Overrides default `~/.omp/agent/sessions/<encoded-cwd>` with explicit directory path.
- **`--no-session`**: Runs in ephemeral memory mode (`persist = false`, backed by `MemorySessionStorage`). No files written to disk; incompatible with resume/continue/restore/fork.
- **`--fork <value>`**: Copies history from an existing session source (id prefix or path) but mints a new UUIDv7 session ID, sets `parentSession: sourceId`, inherits prompt-cache key, copies artifacts recursively in the background, and leaves the parent session completely untouched.

## 4. Concurrent-Writer Behavior (P0)

### Mechanism: Process-Owned OS Advisory Leases
1. **Lock primitive**:
   - `packages/coding-agent/src/session/session-storage.ts:600-632` (`tryAcquireSessionLease(sessionId)`).
   - Backed by `packages/utils/src/file-lock.ts:35-43` (`tryAcquireFileLock`).
   - Target lock path: `~/.omp/run/session-owners/<sessionId>` (or hashed name).
   - **Linux implementation**: Uses Linux abstract Unix domain sockets (`@omp-file-lock-<hash>`). Abstract sockets exist purely in the kernel network namespace, leave zero disk files, and are automatically closed/released by the Linux kernel if the process terminates or crashes (`SIGKILL`).
   - **Windows/macOS**: Windows uses named mutexes; macOS/other Unix uses `flock` sidecars (`<sessionId>.lock`).
2. **Claiming**:
   - `packages/coding-agent/src/session/session-storage.ts:1292-1322` (`FileSessionStorage.claimSession`).
   - Only processes performing **writes** claim the lease (`session-manager.ts:1096-1114`). Read-only tools (`omp share`, `--export`, `render`) open without claiming.

### What Happens When Second Process Opens Active Session
- **Verdict: FORK (Relocates to Sibling File on First Write; Never Overwrites, Never Rejects on Open).**
- **Flow**:
  1. Process B can open and read Process A's session file without error during startup.
  2. When Process B prepares its first write, it checks `this.#sessionOwnedElsewhere()` (`session-manager.ts:1123-1128`).
  3. `this.#claimSession()` calls `storage.claimSession(sessionId, sessionFile)`. Because Process A holds the abstract socket lock, `claimSession` returns `null`.
  4. Detecting ownership elsewhere, Process B invokes `this.#moveOffSessionFile("open-elsewhere")` (`session-manager.ts:1263-1288`, called from lines 1629, 1761, 1880, 1952).
  5. Process B leaves Process A's file completely untouched.
  6. Process B mints a fresh UUIDv7 session ID (`mintSessionId()`), updates header with `parentSession: previousSessionId`, creates a new sibling file `<newTimestamp>_<newSessionId>.jsonl` in the same directory, copies artifacts in the background (`copySessionArtifacts`), rewrites its in-memory transcript to the sibling file, and continues appending there.
  7. Process B issues a `SessionPersistenceNotice` (`reason: "open-elsewhere", from, to`).

### External / Non-Cooperative Writers
If a third-party tool modifies the `.jsonl` directly without acquiring the lease:
- Process detects byte size mismatch on atomic commit -> raises `SessionWriteConflictError`.
- Re-reads file, adopts foreign entries on a side branch, retries up to 3 times (`MAX_WRITE_CONFLICT_RECOVERIES = 3`).
- If conflict persists, moves to a sibling file with `reason: "contested"` (`session-manager.ts:1240-1256`).

## 5. Titles: Generation, Storage, and `--no-title`

### Generation
- Triggered on first turn once user inputs text and assistant begins replying (`packages/coding-agent/src/session/agent-session.ts:10248-10333`).
- Mode `title.generator: fork`: Side turn branched from streaming reply using same model, prompt cache, system prompt, and tools.
- Fallback mode: Title model (`generateTitle` via tiny local model / smol / commit model).
- Title Carding: Prefixes short icon and code (emoji/nerdfonts) via `title-card.md` unless `title.icons: boring`.
- Replan Refresh: Re-titles after plan updates if `title.refreshOnReplan` is enabled.
- User `/rename <title>`: Sets `titleSource: "user"`, preventing future auto-title overwrites.

### Storage
1. **Physical 256-byte Title Slot**: Fast in-place rewrite at line 0 of session JSONL (`session-title-slot.ts`).
2. **Audit Entry**: Appended as `type: "title_change"` record in JSONL stream (`session-manager.ts:3356`).
3. **Session Header**: Updated in-memory and on full rewrites (`header.title`, `header.titleSource`).
4. **SQLite Index**: Cached in `~/.omp/agent/history.db` in table `session_titles` for fast startup listings without scanning JSONL contents.

### `--no-title` Semantics
- CLI flag `--no-title` sets `Bun.env.PI_NO_TITLE = "1"` (`packages/coding-agent/src/main.ts:1968-1975`).
- Also set automatically by `--mode rpc`, `--mode rpc-ui`, `--mode acp`, or env `PI_NO_TITLE=1`.
- When set, `agent-session.ts` `#scheduleReplanTitleRefresh`, `#noteTitleInput`, and `#deferredTitle` return immediately, disabling background title generation.

## 6. How to Detect Live vs. Saved-on-Disk

### Detection Mechanism
1. **Abstract Socket / OS Lock Probe (Universal)**:
   - Call `tryAcquireSessionLease(sessionId)` (`session-storage.ts:600-632`).
   - If returns `null` -> **LIVE** (active writer holds the abstract socket).
   - If returns handle -> **SAVED-ON-DISK-ONLY** (no active writer; caller immediately releases handle).
   - This is the exact mechanism `omp gc` uses to avoid sweeping active sessions.
2. **Collab Host Registry (Collab Mode)**:
   - Active hosts maintain registration in `~/.omp/run/collab-hosts/<instanceId>.json` and an open socket `<instanceId>.sock`.
   - `omp collab list --json` reports active hosts with verified PID and socket connectivity.
3. **Inspect `/proc/net/unix` (Linux OS level)**:
   - Active locks appear as abstract socket addresses matching `@omp-file-lock-*`.

## 7. `omp session pack | unpack | moved` Purpose

*Source:* `packages/coding-agent/src/session/session-transfer.ts:1-75`.

- **`omp session pack <session.jsonl> <output.tar>`**:
  Creates a portable tarball containing `manifest.json` (version 1, session ID, source cwd, omp version), `session.jsonl` (journal byte-for-byte), `artifacts/` (artifacts tree and child sessions), and referenced `blobs/<sha256>`.
- **`omp session unpack <archive.tar> --cwd <new-dir>`**:
  Restores session onto another machine. Installs blobs into local `~/.omp/agent/blobs/`, restores artifacts, rewrites journal header `cwd`, and appends a `custom_message` entry of `customType: "session-transfer"` with `kind: "arrived"`.
- **`omp session moved <session.jsonl> --to <target>`**:
  Marks local session stale after transferring it away. Appends a `session-transfer` `kind: "departed"` record. If a user subsequently attempts to resume the local file, `forkIfMovedAway` automatically forks it into a new session ID (`kind: "forked"`), preventing divergence against the remote copy.
