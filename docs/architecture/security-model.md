# Security model

## Scope and current implementation state

This model describes checked-in implementation, distinguishing component code from complete product path. `apps/server/src/server.ts` wires metadata, authentication, OMP adapters, supervisor, Fastify API, static web hosting (`apps/web/dist` and `packages/guest/dist`), and private relay attachment, running `supervisor.reconcile()` at startup. The API provides session listing, link minting (`POST /api/conversations/:id/link`), attach instructions (`GET /api/conversations/:id/attach`), and runtime status (`GET /api/runtime`). Prompts flow directly over the guest room WebSocket; there is no prompt HTTP route.

The trust model assumes a single owner and an Ubuntu laptop. It does not claim protection from root, a same-UID process, a compromised OMP binary/provider, or a user who deliberately grants a control link to someone else. The agent is intentionally powerful: OMP tools execute as the owner and there is no OS sandbox in this repository.

## System and trust boundaries

```text
trusted owner
  │ trusts their intent, not the phone's security state
  ▼
iPhone / Safari or PWA ── HTTPS/WSS over tailnet ──► Tailscale Serve / tailnet
  │ untrusted hardware, browser, extensions, backups, screenshots              │
  │                                                                           ▼
  └──────────── authenticated HTTP / browser guest ─────► Server on laptop (loopback)
                                                           │ owner identity; password/session;
                                                           │ metadata; can launch owner processes
                          ┌────────────────────────────────┼─────────────────────────┐
                          ▼                                ▼                         ▼
                  tmux + OMP agents                 private Collab relay       session store
                  owner privileges, arbitrary       loopback, ciphertext      metadata JSONL
                  code, no OS sandbox               and routing metadata      │
                          │                                │                  native OMP journals
                          └── host socket / sealed frames ─┴──────────────────┘ ~/.omp/**
```

The arrows are trust boundaries, not claims that every channel is currently reachable or correctly wired. Each crossing has a distinct consequence:

| Boundary | What crosses | Attacker gain if boundary is crossed |
| --- | --- | --- |
| Phone ↔ tailnet / Tailscale Serve | TLS-protected HTTP, session cookie, CSRF header and browser WebSocket frames; room link is a separate bearer secret. | A compromised phone or admitted tailnet device can reach the app and attempt authentication. A stolen session cookie can use authenticated HTTP controls; a control room link can read and steer its live agent. Tailnet membership alone is not app authentication. |
| Tailnet / Serve ↔ laptop server | Serve terminates TLS and proxies to a loopback listener. The app checks an Origin allowlist; optional Tailscale-origin trust is off by default. | Network reachability allows login attempts, but does not itself authenticate. A server exploit gains the owner's OS permissions. Serve identity headers are not bound to the app session. |
| Server ↔ tmux / OMP process | Process arguments, working directory, OMP config/model options and lifecycle requests. | The server can launch and stop owner processes. OMP tools then run arbitrary code with the owner's permissions; no OS sandbox limits filesystem, network or credential access. |
| OMP host ↔ private relay ↔ guest | Host/guest WebSocket binary frames: 4-byte routing prefix plus sealed AES-GCM payload; text controls only report peer lifecycle. | A room-link holder can decrypt transcript and, with write token, steer the agent. Relay learns room/peer IDs, timing, counts and ciphertext sizes, not payload plaintext or key. A reachable attacker can still consume relay resources or disrupt connections. |
| Server ↔ metadata store / native journals | Project/conversation metadata, event/command records and native OMP session files. | Read access reveals project paths, activity, and persisted event/command text. Write access can corrupt app associations and lifecycle records. Native journals and `~/.omp` credentials are separate from the web metadata store. |

Tailscale Serve and loopback are deployment assumptions, not substitutes for app authentication. `apps/server/src/config.ts` defaults the API host to `127.0.0.1`. As built, `apps/server/src/server.ts` binds the API, serves the web build and fallback guest viewer, and attaches the guest room endpoint to the app's HTTP server (`createRelay({ server: app.server, attachOnly: true, allowHost: false })`) on `config.port` (default 8791). A second loopback listener at `config.relayPort` (default 8792) accepts `role=host` upgrades only. That topology allows one public TLS origin for the UI, API, and guest joins, while keeping host upgrades loopback-only. `docs/adr/0002-private-relay-and-remote-access.md` rejects public exposure and requires Serve for remote TLS.

**The proxy is the weak seam, and it is why a peer address proves nothing.** Serve terminates TLS and forwards to the loopback listener, so *every* remote request arrives with a loopback peer address. Any control that trusts `remoteAddress` — including the relay's host-role check — is therefore trusting the proxy, not the caller. This is why the host endpoint is separated onto its own loopback listener (`config.relayPort`) that `tailscale serve` must **never** proxy. Distinguishing our agent from another local process would require credentials OMP cannot present; this separation is a topology control against the network, not agent authentication against local processes on the laptop.

## Assets and impact ranking

Ranks are by practical ability to cause owner-level harm, with the control room link first because it directly steers a privileged live agent. A password/session can also mint that capability: `POST /api/conversations/:id/link` is wired and returns a fresh, generation-bound link on demand.

| Rank / asset | Concrete loss if it leaks | What limits cascading loss (and what does not) |
| --- | --- | --- |
| **1. (a) Control room link** | It contains the room ID, 32-byte AES key and 16-byte write token. A holder can read the live/back transcript and steer the agent, whose tools run as the owner; this can expose SSH keys, provider credentials or any readable file through legitimate agent output. | The link is a bearer credential; OMP validates the write token. Room generations rotate and OMP rejects stale generations; the room exists only while its host room exists. The client fetches links on demand (`POST /api/conversations/:id/link`) and keeps its current credential in React memory (`apps/web/src/components/ConversationView.tsx`), not localStorage. **No fixed time-based TTL is enforced by the current web/server code.** Once stolen, no cryptographic control distinguishes the attacker from the owner. |
| **2. (g) Agent credentials in `~/.omp`** | Provider/API keys, settings, sessions and other OMP state can be stolen or misused; a compromised agent can use credentials the owner configured for it. | The app does not store provider credentials and, per `docs/operations/ubuntu-setup.md`, agents inherit OMP's existing auth. OMP's local filesystem permissions and provider revocation are the boundary. This repository does not sandbox agents from `~/.omp`; owner-account compromise exposes it. |
| **3. (b) Session cookie** | The opaque `__Host-caw_session` cookie authenticates protected HTTP routes. With the current/planned control surface, an attacker can browse allowed roots, change metadata, request room links and launch/stop agents. | `HttpOnly`, `Secure` by default, `SameSite=Lax`, `Path=/`, and no `Domain`, server-side hashed session IDs, expiry and logout revocation reduce theft paths (`apps/server/src/auth.ts`). CSRF and Origin checks prevent another site from riding the cookie. XSS can still act as the owner even without reading an HttpOnly cookie. Session records are in memory and expire; a same-UID attacker can inspect process memory. |
| **4. (c) Password / first-run setup token** | The generated setup token is printed to stdout and immediately persisted as the password hash; the current server has no password-change route, so it does **not** become one-use merely because it is called a setup token. Anyone who reads the service journal can keep authenticating with it. | Password material is stored as salted scrypt output with a 0600 file (`apps/server/src/auth.ts`); random session IDs are not stored raw. Login has per-IP and global exponential backoff. The setup token is not safe if stdout/journals are exposed, and there is no app-level Tailscale identity binding or password-reset route in the current server. |
| **5. (e) Ability to launch an agent** | An attacker can start arbitrary agent work as the owner, consume provider credits/resources, and cause filesystem/network side effects. | Protected HTTP routes, CSRF, the configured concurrency ceiling and the duplicate-writer guard limit access and accidental duplication. There is no OS sandbox or per-agent credential boundary; a successful control-plane compromise is owner-account compromise. `apps/server/src/server.ts` wires the supervisor into `buildApp()`. |
| **6. (f) Metadata store** | `metadata.jsonl` can disclose projects, conversation titles/IDs, event payloads and idempotency command payloads; tampering can alter UI/runtime associations. | It is local, created under a state directory requested with mode 0700, and new metadata files use mode 0600 (`apps/server/src/store.ts`). It stores no Collab link by design. The store is append-only JSONL and not encrypted; existing directory/file permissions are not explicitly tightened. Same-UID malware and backups remain in scope for the owner to manage. |
| **7. (d) Folder-browser surface** | It returns canonical paths, names, directory flags and allowed-root membership, enabling reconnaissance. It does not return file contents. | `WorkspacePathPolicy` scopes browsing to configured roots and the API requires an authenticated session (`apps/server/src/path-policy.ts`, `apps/server/src/app.ts`). Symlink/path race hardening is incomplete for a concurrent attacker; the folder browser is not an OS access-control boundary for OMP itself. |

## Threats, controls and residual risk

“Implemented” below means source exists; it does not imply the app currently wires the component into a production request path. Gaps are explicit.

| Threat / attacker path | Control implemented or required | Residual risk accepted |
| --- | --- | --- |
| **Stolen or unlocked iPhone** | Require the app password and server-side session for protected API routes (`apps/server/src/app.ts`, `apps/server/src/auth.ts`). Cookie is `HttpOnly`, `Secure` unless the explicitly local-only `insecureCookies` option is set, `SameSite=Lax`, `Path=/`, and has no `Domain`. Logout currently revokes **all** in-memory sessions via `revokeAll()`. Keep Tailscale device key expiry/revocation enabled (`docs/operations/iphone-setup.md`, `docs/research/security-considerations.md`). | An unlocked phone with a live session is the owner until logout, expiry or tailnet revocation. An attacker can use the UI to exercise legitimate owner powers and view visible agent output. No MDM, remote wipe, device biometrics, or per-device session-revocation UI is implemented. |
| **Leaked control room link** | Treat full links as bearer credentials and never log, persist, notify or place them in generated URLs. The web client holds the raw link in a component ref and clears it on unmount (`apps/web/src/components/ConversationView.tsx`); relay traffic carries only ciphertext (`packages/relay/src/relay.ts`). OMP room-generation changes invalidate old links (`packages/omp-adapter/src/collab-registry.ts`, `docs/research/omp-compatibility.md`). Fetch fresh on demand; require `Cache-Control: no-store` on a future link response. | A stolen link remains usable for that room generation while its host is live. “Short-lived” currently means room-lifetime/generation-lifetime and in-memory handoff, **not a separately enforced wall-clock TTL**. The app route and no-store response are not implemented yet. Anyone with control access can prompt an unsandboxed owner-privileged agent. |
| **Compromised Tailscale account or admitted device** | Keep Serve behind tailnet ACLs and app password/session; bind listeners to loopback (`apps/server/src/config.ts`, `packages/relay/src/relay.ts`). API middleware requires a valid Origin on mutations, rejects cross-site fetch metadata and requires session CSRF (`apps/server/src/app.ts`); `trustTailscaleOrigin` defaults false. | A compromised device can reach login, attack credentials, or use any stolen cookie/link. Serve-injected identity headers are not verified or bound to an app session. Tailnet admin can change ACLs. The server supplies no custom Origin allowlist, and the default permits localhost origins only; remote mutations from a Tailscale Serve origin therefore need `trustTailscaleOrigin` or an explicitly configured allowlist. Tailnet membership is not owner intent. |
| **XSS via agent-authored Markdown, tool output or file text** | The main web renderer uses React nodes rather than injecting Markdown HTML; `apps/web/src/sanitize.ts` permits limited URL schemes and escapes text. Vendored guest Markdown escapes raw HTML, gates links/image sources and uses `rel="noopener noreferrer"` (`packages/guest/src/components/transcript/Markdown.tsx`). Guest CSP is in `packages/guest/index.html`; Fastify responses set CSP, `nosniff` and `no-referrer` (`apps/server/src/app.ts`). | Main document `apps/web/index.html` has no CSP; Fastify does not serve it (`apps/server/src/server.ts`). Main sanitizer allows remote HTTPS images and any `data:image/` prefix (`apps/web/src/sanitize.ts`), leaving outbound image fetches and a broad data-image allowance; no strict image MIME/base64 allowlist. Vendored guest has CSP but allows `https:` images. `dangerouslySetInnerHTML` remains in guest Markdown and optional tool-highlight paths, so safety depends on sanitization. XSS can issue authenticated actions as the user even when it cannot read an HttpOnly cookie. |
| **CSRF / cross-site WebSocket hijacking** | Safe HTTP methods are exempt from JSON and CSRF checks; mutating requests require an allowed Origin, reject non-same-origin `Sec-Fetch-Site`, and require session CSRF except login (`apps/server/src/app.ts`, `apps/web/src/api.ts`). Relay checks browser Origin/fetch metadata (`packages/relay/src/relay.ts`); its room protocol relies on room key/write token rather than app cookie, and native OMP without Origin is admitted. | The previous GET middleware defect is fixed in source (`SAFE_METHODS` now gates JSON/CSRF checks), but `tests/server/app.test.ts` does not assert successful safe GET without JSON/CSRF. Remote mutation Origin configuration remains a deployment gap as described above. A stolen valid room link bypasses web CSRF by design. |
| **Directory traversal / symlink escape** | Requests are zod-validated (`browseQuerySchema`, max path 4096); path policy rejects non-absolute paths, NUL, dot segments, separators/control chars, normalizes NFC, resolves components and uses segment-aware containment against real roots (`packages/contracts/src/index.ts`, `apps/server/src/path-policy.ts`). Static relay assets use one URL decode, segment checks, `O_NOFOLLOW`, handle `stat`, and root containment via `/proc/self/fd` when available (`packages/relay/src/static.ts`). | Workspace browsing currently lists directory names only; it does not open or serve arbitrary file contents. In `WorkspacePathPolicy`, `realpath` follows symlinks and containment occurs after resolution; symlinks resolving within a configured root are allowed. The policy does not open a handle for the listing operation. |
| **TOCTOU between path check and open/list** | Static assets use `O_NOFOLLOW` and check the opened descriptor's real path under the static root (`packages/relay/src/static.ts`). The workspace path-policy comment explicitly requires future file opens to use `O_NOFOLLOW` and `fstat` (`apps/server/src/path-policy.ts`). | Workspace `assertInsideRoots()` / `listDirectory()` perform check-then-`readdir`; an OMP agent can mutate the tree concurrently. There is no descriptor-relative traversal or handle-based root check for workspace browsing, and no arbitrary workspace file-open endpoint yet. Treat a future file read/open feature as blocked on closing this race, not as covered by `realpath`. The static handler's fallback when `/proc/self/fd` cannot be read uses `realpath(filePath)` after open and leaves a race on that platform. |
| **Malicious or weird project/file names** | Schema bounds project labels to 120 characters and paths to 4096. Path components reject `.`/`..`, slash/backslash and C0/DEL controls; NFC matching rejects ambiguous normalized path components (`packages/contracts/src/index.ts`, `apps/server/src/path-policy.ts`). Displayed names are text in React. | Bidi controls, zero-width/confusable Unicode, slash-like lookalikes, leading/trailing spaces and long individual directory names are not comprehensively rejected or annotated. NFC normalization can make different filesystem byte names display identically; path policy rejects ambiguous input matches but listings can still expose confusing names. No test covers every display-spoofing case. |
| **Command / argument injection into `tmux` or `omp`** | Adapters invoke binaries through `execFile`/argv with `shell: false`; OMP registry commands also use argument arrays (`packages/omp-adapter/src/tmux.ts`, `packages/omp-adapter/src/collab-registry.ts`). Tmux session names are sanitized. Launch uses `new-session -P -F '#{session_id}'` and returns tmux's `$N` ID. | `LaunchRequest` fields (`cwd`, config path, model, extra args, environment) are internal types, not validated by an HTTP schema at the adapter boundary. Tmux's command semantics still need injection-focused regression tests. `sendKeys()` passes a string as keystrokes; if an untrusted caller ever supplies it, it can type commands into the agent shell. No app prompt endpoint currently calls it. |
| **Prompt injection inside agent-visible content** | No detector is claimed. Keep the damage boundary explicit: agent output/input is adversary-controlled; require the owner to make tool-approval decisions in OMP, do not auto-approve on disconnect, and report approval/timeouts honestly. Agent sessions are separate tmux processes and `maxActiveAgents` caps concurrent sessions (`packages/runtime/src/supervisor.ts`, `apps/server/src/config.ts`). | Prompt injection cannot be reliably detected by this web layer. OMP can still be induced to use the owner's accessible files, network and credentials; configured folder roots limit only this app's folder browser, not agent OS access. There is no seccomp/container/OS sandbox or distinct low-privilege agent identity. Residual accepted: anyone with a control link can manipulate owner-privileged agent behavior. |
| **Backend privilege escalation** | Run as the normal owner, never root (`docs/operations/ubuntu-setup.md`). Server binds loopback by default; request bodies use shared schemas and process calls use argv with `shell: false` (`apps/server/src/config.ts`, `apps/server/src/app.ts`, `packages/contracts/src/index.ts`, `packages/omp-adapter/src/tmux.ts`). | Server RCE equals owner-account compromise: read `~/.omp`, modify files and launch arbitrary user processes. No sandbox, privilege separation, syscall filter or separate agent identity exists. |
| **Orphaned OMP process after disconnect, crash or restart** | Browser close closes its guest socket but does not stop host process; relay host loss closes the room (`packages/relay/src/relay.ts`). Server startup runs reconciliation through the wired supervisor (`apps/server/src/server.ts`, `packages/runtime/src/supervisor.ts`), which does not kill processes it cannot associate safely. | Agent may continue using resources or running tools after phone/server disconnect. Current reconciliation iterates stored conversations; it does not adopt an unrecorded `caw-` tmux session, so such a process can be orphaned. Orphan-without-metadata recovery remains a gap; no automated recovery should guess that a process is safe to kill. |
| **Session-ID confusion / wrong tmux target** | Conversation, native session UUID, tmux `$N`, host instance ID/generation and room ID are distinct (`docs/architecture/session-lifecycle.md`, `packages/contracts/src/index.ts`). Supervisor uses recorded `$N` exclusively when present and stops by that ID (`packages/runtime/src/supervisor.ts`). Attach endpoint now emits recorded `$N`; tmux name is display-only (`apps/server/src/app.ts`). | Legacy/id-less conversations may still be adopted by `caw-` name (`packages/runtime/src/supervisor.ts`); tmux names share a namespace and can be reused, so this recovery fallback retains a name-reuse hazard until the ID is recorded. Adapter accepts any string beginning `$` rather than strict `$[0-9]+` (`packages/omp-adapter/src/tmux.ts`). Add id-less reused-name and strict-ID tests; never accept client-supplied tmux/native ID as authorization. |
| **Unauthorized command execution** | Protected API routes require a valid session; mutating HTTP requests require Origin and CSRF. OMP Collab validates the write token for guest writes; view links omit it (upstream contract in `docs/research/collab-data-model.md`). API route bodies use schemas in `packages/contracts/src/index.ts`. | There is no prompt HTTP route, so server-side command authorization/idempotency-before-forwarding is not implemented. A control room link itself authorizes guest commands. Lifecycle routes and link issuance (`POST /api/conversations/:id/link`) are wired; prompt delivery is direct over the authenticated/bearer room WebSocket. Never translate arbitrary phone text into `tmux send-keys`. |
| **Accidental disclosure in logs, notifications, referrers or crash reports** | Fastify disables default request logging and emits method/route/status/origin, not URL or body (`apps/server/src/app.ts`, `apps/server/src/logger.ts`). Its error handler redacts messages with `redactLogValue()`. Relay log API never receives frame bytes; static responses set `Referrer-Policy: no-referrer` (`packages/relay/src/relay.ts`, `packages/relay/src/static.ts`). The owner UI keeps link in a React ref and does not create generated URL or localStorage handoff (`apps/web/src/components/ConversationView.tsx`). | `redactLogValue()` is not a universal logger/crash chokepoint; actual request/error-log capture and relay-log scans are untested. Relay logs room IDs and routing metadata. Vendored standalone guest stores a supplied link in `window.location.hash` (`packages/guest/src/app.tsx`), which can enter history/screenshots; do not use it as owner dashboard handoff. No notifications or crash reporter are wired. Main web index only has a no-referrer meta tag; its hosting headers need separate verification. |
| **Password guessing / setup-token theft** | `apps/server/src/auth.ts` uses 32-byte random first-run setup token, salted scrypt hash, timing-safe password compare and in-memory exponential per-IP and global backoff. | Rate state resets on server restart and the IP observed behind a loopback proxy may not distinguish tailnet devices. Setup token is printed to stdout and may persist in journald. A compromised service account can read the stored hash, process state and OMP credentials. |

## Explicitly rejected controls

- **Do not auto-approve tool calls when the phone disconnects.** A dropped socket is not owner consent; OMP approval timeouts must fail closed. Disconnect detaches a viewer, never upgrades trust (`docs/architecture/session-lifecycle.md`, `docs/architecture/mobile-client.md`).
- **Do not bind to `0.0.0.0` for convenience.** It expands access to LAN interfaces and breaks the loopback + Serve trust boundary. Keep `host=127.0.0.1` and `relayHost=127.0.0.1` unless an operator consciously documents an unsafe override (`apps/server/src/config.ts`, `packages/relay/src/relay.ts`).
- **Do not store a room link in localStorage, IndexedDB, a service-worker cache, or a generated URL.** Script-readable persistence survives the live component and expands XSS/history/share leakage. The main UI uses an in-memory ref; fetch links again when needed (`apps/web/src/components/ConversationView.tsx`).
- **Do not use Tailscale Funnel.** Funnel publishes the control plane beyond the private tailnet, contrary to the owner-only boundary (`docs/adr/0002-private-relay-and-remote-access.md`).
- **Do not kill sessions by name, PID, or process-name glob.** Tmux names are labels, PIDs can be reused, and broad process matching can kill unrelated owner work. Stop only recorded tmux session IDs (`packages/runtime/src/supervisor.ts`).
- **Do not treat `busy === false`, a closed socket, or a server restart as proof an agent finished.** These are not process/journal facts; retain `unknown` where observations fail (`packages/runtime/src/state.ts`, `docs/architecture/session-lifecycle.md`).
- **Do not implement an agent-loop or parse terminal output to infer structured events.** Use native OMP Collab and its sealed protocol; it avoids a second authority and a terminal scraper (`docs/adr/0001-runtime-architecture.md`).
