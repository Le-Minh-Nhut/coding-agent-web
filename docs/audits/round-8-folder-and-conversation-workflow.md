## Round 8 follow-up — directory creation hardening

Fixes for two source-confirmed defects in `WorkspacePathPolicy.createDirectory`:

### 1. Defect 1 — Parent TOCTOU race (`apps/server/src/path-policy.ts:139-152,163-178`)
- **Fix (b) tightened parent binding**: immediately before `mkdir`, `realpath(parent)` is re-evaluated; mismatch against canonical validated parent refuses with `path_forbidden` ("Parent directory changed during creation").
- **Fix (a) post-creation containment assertion**: after `mkdir` succeeds, `realpath(target)` is computed and checked against configured roots via `this.inside(canonicalTarget, roots)`. If outside, honest refusal `PathPolicyError("path_forbidden", "Created directory is outside configured workspace roots")` is thrown without attempting deletion or unlinking.
- **Residual ceiling**: races a local actor who already has shell on the machine; we detect-and-refuse rather than guarantee atomicity because `node:fs` lacks a portable `mkdirat` descriptor binding. The created directory is left in place outside the allowlist rather than unlinked, prioritizing safe refusal over deletion.

### 2. Defect 2 — Unicode-equivalent name collision (`apps/server/src/path-policy.ts:127-137`)
- **Fix**: before `mkdir`, `readdir(parent)` reads current entries and compares each entry under NFC normalization (`entry.normalize("NFC") === name.normalize("NFC")`). If an equivalent entry exists, refuses with `PathPolicyError("already_exists", "A file or directory with that name already exists")` prior to invoking filesystem mkdir, leaving on-disk entries unchanged. The `EEXIST` catch block remains on `mkdir` as a backstop for concurrent identical creates.
