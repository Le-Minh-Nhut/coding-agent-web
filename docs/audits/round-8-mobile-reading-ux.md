## Scroll-behavior verdict

**Forced scrolling is present; scrolling up to read older content is not respected during streaming.** Exact cause: `ConversationView.tsx:70-75` watches `[messages, streamingText]` and calls `messagesEndRef.current.scrollIntoView({ behavior: "smooth" })`. `message_update` updates `streamingText` at `ConversationView.tsx:152-159`; completed messages and tool results update `messages` at `160-181` (and history entries at `112-140`). The sentinel is at `642`.

No threshold/reader lock or “jump to latest” button exists in this component (`ConversationView.tsx:518-669`). The only `scrollIntoView` / scroll position write in the audited web source is this effect. The other user-visible scrolling is CSS overflow in `styles.css:224-231,301-312,362-370`; it does not implement a tail lock.

## Requested behavior inventory

- **Markdown:** custom allowlist renderer in `sanitize.ts`, not a library (`sanitize.ts:9-10,139-229`). Headings only through `###`; unordered list items are bare `<li>`; tables/ordered lists unsupported; ordinary nonblank lines become separate paragraphs (`181-214`). HTTPS links only; images allow HTTPS/data-image schemes (`sanitize.ts:11-22,56-75,78-100`).
- **Horizontal overflow:** code `<pre>` uses internal `overflow-x:auto`; mobile E2E checks that a 400-character code line scrolls inside `<pre>` and does not widen the page (`styles.css:301-326`; `tests/e2e/mobile.spec.ts:112-137`). No table element is emitted by the current Markdown renderer. Long plain/inline message tokens lack an explicit wrap rule (`styles.css:256-280`); add one on message content, not on `<pre>`. Project paths already break at `ProjectDetailView.tsx:71-73,142-144`.
- **Code blocks:** monospace and whitespace preservation: **WORKING** (`sanitize.ts:155-161`; `styles.css:302-325`). Send button and `isSending` guard prevent duplicate sends; existing unit test covers this (`ConversationView.tsx:320-339,661-668`; `tests/web/composer.test.tsx:57-115`). Minimum space-saving change: collapse only model editing; do not hide connection status or composer.
- **Performance / virtualization:** every streaming update rerenders all mapped settled messages and reparses the growing stream (`ConversationView.tsx:152-159,561-585`). ### Current scroll verdict

Streaming no longer forces readers to the tail when detached. `updateTailLock` measures distance from bottom and marks detached above 80px (`ConversationView.tsx:185-191`). `useLayoutEffect` writes `scrollTop` only when `followTailRef.current` remains true (`193-196`), and the `ResizeObserver` follows content/viewport size only under the same lock (`198-212`). “Latest” sets the lock and scrolls to bottom (`222-228`), rendered while detached (`619`). Browser measurement: at 390×844, transcript `scrollHeight=6508`, `clientHeight=583`; document height `844` equals viewport `844`. Scrolling up set `scrollTop=120` and exposed “Latest”; appending and expanding output both kept it at `120`; Latest restored `scrollTop=8328` to bottom `8328` (`tests/e2e/mobile.spec.ts:159-229`).
